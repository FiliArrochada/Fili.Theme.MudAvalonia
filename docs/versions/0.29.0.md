# 0.29.0

[All versions](README.md)

The last minor before 1.0: the published keys and classes are frozen in a file the tests hold the
theme to, and `FiliFontSize` now sets the app's text size. Behaviour the templates had silently
dropped works again (an editable select, a scroll bar's paging, a calendar from the keyboard, a
switch's drag), a screen reader hears every icon button, upper-case label and validation error the
theme draws, and reduced motion stops every transition. Keyboard focus now draws a ring in every
variant. A few fields, grids and switches look slightly different, each listed under
[Upgrading](#upgrading-from-0280-to-0290).

## What changed

### The interface and releases

- **`FiliFontSize` is the app-wide text size.** Every window and popup takes its size from it,
  where they read `FiliBody2FontSize`, so an app that sets it in the application's `Resources`
  scales all unclassed text. Its default is body2's 14, as before. `FiliLineHeight` and
  `FiliLetterSpacing` are documented for what they are: the baseline's line and tracking for an
  app's own styles, which the theme puts on no unclassed text.
- **The published interface is frozen in `published-baseline.txt`.** Every published key with the
  type it resolves to in each variant, and every class, in a test file that only grows. A key or a
  class removed from the source and its documentation together now fails the build, as does a key
  that changes type.
- **The package's release notes are on nuget.org:** the version page's summary and a link to the
  rest, where the tab was empty.
- **Stepping into the theme's XAML works from a published package.** The XAML compiler keeps the
  build machine's paths, which Source Link did not map, so a debugger found no file; the package's
  Source Link now maps them to the commit on GitHub too.
- **The build is held to what it is today:** warnings fail it, every restore on CI is locked to the
  packages each project's lock file records, a style-instance ceiling on a screen of 1,600
  controls fails a selector that multiplies, and a BenchmarkDotNet project times that screen with
  the theme and with the forked base alone.

### Controls

- **An editable select takes typing.** `IsEditable="True"` on a ComboBox took focus and ignored
  every key: the template had no `PART_EditableTextBox`, which Avalonia looks up without
  complaint. The input now sits in the selected item's place inside the same field; typed text
  floats the label as a value does, and the input is the one Tab stop.
- **A scroll bar keeps Avalonia's behaviour.** A click on the trough pages again, the content
  waits for the release under `ScrollViewer.IsDeferredScrollingEnabled`, and a right-click opens
  Avalonia's Scroll here / Top / Page up menu. The rail looks as it did: the page buttons are
  transparent, and there are still no line buttons.
- **A calendar takes the keyboard, and shows where it is.** The calendar is now a Tab stop of its
  own, where nothing in it could take focus, and the day, month or year the arrow keys are on has
  the focus ring's 2px of text-primary round it. Before, in the year and decade views and in a
  range selection, nothing showed it.
- **A standard field's label rests on its text line.** Empty and unfocused, a standard text field's
  or select's label sat centred in the field, 7px above the line its value is typed on (6.5 dense);
  it now rests where `_inputlabel.scss` puts it. Filled and outlined labels stay centred in their
  box, as MudBlazor's are. Fields built on the text field (number, date, time, autocomplete) follow.
- **The time picker's popover has a height limit, Avalonia's 398px,** so the offset Avalonia works
  out from it for its own, empty, popup is finite. The popover is 372px and is not cut.
- **A switch's thumb follows a drag.** Avalonia moves the knobs by `Canvas.Left`, and the template
  slid the thumb with a transform, so a drag still toggled on release while the thumb stood still
  under the pointer. The thumb now rides where Avalonia puts it, at rest exactly where it was.
- **A slider takes a click anywhere in its row.** The rail is 2px, 4 or 6 to look at, and was that
  to hit; a click beside it now moves the thumb there, as a range input's does.
- **A long label ends in an ellipsis.** A text field's or select's label longer than the field ran
  past it and under the clear button, an end adornment or the arrow; it now stops at the text's
  column. So does a data grid column's title, before its sort button.
- **A data grid's sort button takes room only on a column that can sort,** as MudDataGrid renders
  it only on a Sortable one: a column with `CanUserSort="False"`, or every column of a grid with
  `CanUserSortColumns="False"`, gives its title the 30px. The grid's scroll bars take their 8px
  rail's width, where they kept a 12px column.
- **A circular progress's text fits its ring.** `ShowProgressText` on the small, 24px ring drew
  "100%" wider than the ring; the text now shrinks to fit inside it, and only where it must.
- **A calendar's arrows are transparent at rest,** as icon buttons are, with the hover tint under
  the pointer: they painted the surface, a pale disc wherever the calendar was not on the surface.

### Accessibility

- **Every icon button in the theme's own templates has a name.** The time picker's OK and Cancel,
  a number field's spinners, a calendar's and a carousel's arrows, a snackbar's close and a text
  field's clear button were read by their content's type ("Avalonia.Controls.PathIcon"), and the
  clear button's "Clear" was fixed English. Each now reads a new `FiliString*` key
  ([Published keys](../published-keys.md#strings)), English by default, which an app sets in its
  `Resources` to translate. The time picker's icon button is hidden from automation, as the date
  picker's is: the field is the picker's one name.
- **An upper-case label reads as written.** A button's, FAB's, split button's or tab's label is
  drawn upper case, and a screen reader read that drawn text, "SAVE", which some readers spell out.
  The control is now named with its label as written, below any name the app sets.
- **High contrast:** the disabled-text figure on the page is 13.6:1, not "about 12:1".
- **Keyboard focus draws a ring in light and dark too.** `FiliFocusRing` is `True` in every
  variant, where it was on in high contrast only: a 2px text-primary ring 2px outside the control
  focused by Tab or the arrows, 10:1 on the light background and 7:1 on the dark. MudBlazor's
  state-layer tint, the only indicator before, is about 1.1:1 and a keyboard user loses it. A click
  or a touch draws no ring. `False` in the application's resources keeps the tint alone.
- **The focus ring follows the control's corners,** each 4px larger, where it was a fixed 4px
  rectangle: a pill gets a pill round it, a square a square. A switch's ring frames the switch,
  its track and thumb, not the switch and its label.
- **An editable time picker opens from the keyboard.** Alt+Down or F4 commits what was typed and
  opens the picker, as it opens a drop-down; Enter commits and Space types, so the mouse was the
  only way in. A read-only picker takes them too. An `AutomationProperties.LabeledBy` on the
  picker names its field, as on every other field.
- **Reduced motion stops every transition the theme declares.** `FiliReducedMotion` stopped the
  ripple, the fades, slides and pulses, and left eight transitions running: the drawer's slide, the
  switch thumb's travel, a field's floating label and focus underline, the chevrons, an expansion
  panel's margin, a determinate circle's sweep, the data grid's sort arrow and the slider's value
  label. Each now happens at once, as do the hover and selection fades, and each comes back when
  the key turns off. An indeterminate progress indicator still moves, and an app's own
  transitions are left alone.
- **A field's validation error reaches a screen reader.** The error replaced the helper text on
  screen only; the field's automation help text stayed the helper text. While a text field, a
  select, a picker or a number field shows an error, the error is now its `ItemStatus`, which a
  screen reader reads with the field; an `ItemStatus` the app sets wins.

### Fixes

- **A menu opened from an icon button keeps its own icon size.** `Button.icon.small` and `.large`
  sized every `PathIcon` they reached, and a selector reaches into the menus, flyouts and tooltips
  a control opens, so a kebab menu on a small icon button drew its rows' icons at 20px (36 on a
  large one). They size the button's own icon only, as does `Button.fab`. A DataGrid's dense
  checkbox likewise stops at the cell's own boxes and no longer shrinks one in a flyout opened
  from a cell or header.
- **A press no longer keeps its window alive.** The ripple remembered the last press until the
  next one anywhere, and with it the pressed control's window after it closed; an app's leak
  test found the last-clicked window still reachable. It lets go once the press has routed.
- **High contrast's forked split-button border is the divider's colour,** `#9C9CA8`, as its brush
  twin always was: the raw `ThemeBorderLowColor` had been left at `#E8E8EE`. A test now holds every
  raw bridge colour to its token in each variant.
- **A page taken out of its window no longer waits for its ripples.** A fade still under way kept
  its button, and the button its page, until the fade's timers fired; leaving the tree now stops
  them, and a test checks that a page the theme worked on is collected.
- **The palette, type ramp and geometry are built once.** The theme include merged them a second
  time over the base include's copy, a second set of every token and brush in every app; they
  now come from the base include alone. High contrast's elevation rings are built once per
  variant rather than on every lookup.

### Documentation

- **An Accessibility page** on the docs site, and a section in the README: what the theme does
  for keyboard, screen-reader and low-vision users, what it leaves to the app (its own icon-only
  buttons' names, following the system's contrast and motion settings, announcing a new error the
  moment it appears), and the contrast of the default light and dark pairs that fall below WCAG AA. No
  conformance is claimed.
- **The Avalonia requirement is stated:** 12.1.4 or later, below 13, with every `Avalonia*`
  package on one version, and what NU1605 on restore means. A control type a later Avalonia 12
  adds stays unthemed until a theme release covers it.
- **A DataGrid outside its supported range shows nothing**, not its own package's look as two
  pages said: the theme skips its templates, and Avalonia has no default theme.
- **Troubleshooting** covers FluentTheme left in, an include built in C# and trimmed away, the
  browser's missing scripts, `x:Key="HighContrast"` and NU1605, and links the published keys.
- **Theming** shows the font, the corner radius and density: a replacement font needs the Light,
  Regular and Medium faces, `FiliCornerRadius` sets every control's corners, and `dense` is set
  per control, with no app-wide switch.
- **Reduced motion** says plainly that Avalonia does not report the system's setting, and lists
  what stops, now everything but an indeterminate progress indicator.
- **A window's own variant** is described as it behaves: it does not restyle the window, where
  the docs said half of it followed.
- **A plain style outranks an app's own `ControlTheme`** for a few `SplitView`, `DrawerPage` and
  `DatePicker` values, now in [Compatibility](../compatibility.md).
- A bug-report issue template, and a "report a bug" row in the README.
- **The docs site says when it runs ahead of the release.** It deploys from `master`, and its
  version label now reads "+ unreleased" while there is work not yet in a package, where it named
  the last release.

## Upgrading from 0.28.0 to 0.29.0

- **Keyboard focus now draws a 2px ring in light and dark,** as it did in high contrast. Set
  `FiliFocusRing` to `False` in the application's resources to keep 0.28's tint-only look:
  `<x:Boolean x:Key="FiliFocusRing">False</x:Boolean>`. A click or a touch draws no ring either
  way; a pixel baseline of a control focused by the keyboard moves.
- **An app that set `FiliFontSize`** sees it take effect: its windows' and popups' unclassed text
  takes that size. Remove the setting to keep 14, or set it to the size wanted.
- **A standard text field or select with no value** shows its label 7px lower (5px dense), on the
  text line. Nothing to change; a pixel baseline of such a field moves.
- **A Calendar** is now a Tab stop, so Tab order through a page with one gains a stop. Set
  `Focusable="False"` on it to keep it out.
- **An icon button whose icon sits inside a panel or another control** (not the button's direct
  content) no longer has the icon sized for it: put the `PathIcon` directly in the button, or size
  it. An icon directly in the button, as the docs show, is unchanged.
- **A DataGrid template column** whose checkbox is nested deeper than the cell's root panel keeps
  a standard checkbox's size. A box directly in the cell or in its root panel is unchanged.
- **A scroll bar** pages on a trough click and has a context menu. An app that relied on the
  trough doing nothing can set `ContextFlyout="{x:Null}"`; the paging is Avalonia's own behaviour.
- **A ComboBox with `IsEditable="True"`** now takes typing and binds `Text`, as Avalonia's own
  does; one that relied on it staying a plain select sets `IsEditable="False"`.
- **A switch's template** puts the thumb, halo and ripple in `PART_MovingKnobs` inside a
  `PART_SwitchKnob` canvas, moved by `Canvas.Left`, where they were slid by a `translateX`
  transform, and adds a `PART_FocusTarget`. An app style that reached the old parts through
  `/template/` (a thumb's transform, say) re-targets them; a switch looks as it did at rest.
- **A slider** moves its thumb on a click up to 17px either side of its rail, where only the rail's
  2-6px took one. Nothing to change.
- **A UI-automation test that found a button, FAB or tab by its upper-case name** ("SAVE") finds it
  by the label as written ("Save"); one that found the theme's icon buttons by a type name finds
  them by their `FiliString*` name.
- **The focus ring** follows each control's corners, and frames a switch without its label.
  Nothing to change.
- **A data grid column that cannot sort** shows 30px more of its title, and the grid's scroll bar
  columns are 4px narrower, so its cells gain the room. A pixel baseline of either moves.
- **A long field label or column title** now ends in an ellipsis where it ran on.
- **A calendar placed off the surface** no longer shows pale discs behind its arrows.
- **An app with `FiliReducedMotion` on** sees the theme's remaining transitions stop too: labels,
  underlines, the switch thumb, chevrons and hover fades change at once. Nothing to change.
- **An app that set `ItemStatus` on a field** keeps its own; one that did not now has the field's
  validation error there while it shows.
- **An app that included only `FiliTheme.axaml`,** without the base include the README requires,
  no longer gets the tokens from it: include both, base first.
