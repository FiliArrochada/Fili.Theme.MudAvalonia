# 0.22.0

[All versions](README.md)

Fixes the docs site turned up, building a page for every component, and the docs themselves moved
into that site. The label beside a `start-icon` or `end-icon` is centred on the icon, as
`.mud-button-label`'s flex row centres them: left to stretch to the icon's 20px, a `TextBlock` drew
its text at the top of that box, 2px above the icon's middle, on buttons, chips, extended FABs and
every other host of an icon slot; and so is the label beside a chip's `avatar`. `button-group` on a
StackPanel of ToggleButtons is MudToggleGroup's shape: the radius on the outer corners and outlined
items sharing one line, where each item kept its own corners and two met in a 2px line. A link is
underlined: `underline` and the default hover underline set nothing, as the style looked in the
template for a TextBlock that a string's AccessText and the app's own text never were. Selecting a
tab scrolls only its bar, where it scrolled the page to the bar; a scroll button at its end has an
action-disabled arrow; and a tab bar's elevation shadow is no longer clipped. A carousel's bullets
are its text colour, as MudCarousel's `Color.Inherit` bullets are, where the current one was primary
and vanished on a primary slide. A list row and a `list-item` take a `start-icon` as MudListItem's
Icon: 24px in a 56px column, action-default, the text centred on it; and an icon helper's earlier
value no longer outlives a later one, so a button inside a list row keeps its own icon colour. A
snackbar's elevation shadow is no longer clipped by the wrapper its close animation scales, and an
alert's icon rules reach only the alert's own icon, not the X in a close button inside it. A tooltip
placed `Top`, `Bottom`, `Left` or `Right` sits centred on that side, 10px from its target, as
MudTooltip's does, arrow or not: Avalonia's 20px `ToolTip.VerticalOffset`, meant for the pointer,
put a `Top` one over its target and `Left` and `Right` ones 20px low, and only an `arrow` tooltip
had a gap. The time picker's popover has its elevation 8 shadow, which the presenter clipped to its
own edge. The usage docs are now the [docs
site](https://filiarrochada.github.io/Fili.Theme.MudAvalonia/), one page per component with live
examples and a parity table, each at its own address; `docs/controls.md`,
`docs/mudblazor-parity.md`, `docs/known-gaps.md` and `docs/razor-vs-axaml.md` are gone, and `docs/`
keeps what a contributor needs. See [Upgrading from 0.21.0 to 0.22.0](#upgrading-from-0210-to-0220).

## Upgrading from 0.21.0 to 0.22.0

No class or key is renamed or removed. Some things look different, as MudBlazor's do:

- **A tooltip placed `Top`, `Bottom`, `Left` or `Right`** now sits centred on that side, 10px off.
  If your app set `ToolTip.VerticalOffset` to pull one back into place, remove it: an offset the
  app sets still applies, now from MudBlazor's position.
- **A label beside a `start-icon`, `end-icon` or a chip's `avatar`** is centred on it. A margin
  or `VerticalAlignment` your app added to nudge it can go.
- **An icon in a list row or a `list-item`** is 24px in a 56px column, in action-default. Size,
  colour or margin your app set on it by hand can go; its own values still win.
- **A carousel's bullets** are its text colour; set `Foreground` on the carousel for another.
- **Links to the old docs**: `docs/controls.md`, `docs/mudblazor-parity.md`, `docs/known-gaps.md`
  and `docs/razor-vs-axaml.md` are gone. Their pages are on the docs site, at
  `https://filiarrochada.github.io/Fili.Theme.MudAvalonia/#<page>`.
