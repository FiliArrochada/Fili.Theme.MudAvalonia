# 0.27.0

[All versions](README.md)

The package's notices and licence name everything it bundles, the docs stop promising more than the
theme does, high contrast reads where it did not, keyboard focus can be a ring rather than the
state layer's faint tint, and a screen reader names each field by its label. A user control in a
coloured host takes the host's text ([Upgrading](#upgrading-from-0260-to-0270)).

## What changed

### Accessibility

- **A focus ring, `FiliFocusRing`**: a 2px text-primary ring 2px outside whichever control the
  keyboard focuses, in every window and popup; a click draws none. On in high contrast; `True` in
  the application's resources turns it on in light and dark, 10:1 and 7:1 on the background, and
  `False` turns it off in high contrast. MudBlazor has none: its state layer's 6% tint, still drawn
  under the ring, falls short of the 3:1 WCAG 2.2's 1.4.11 asks of a focus indicator, as the
  Keyboard focus page now says. The ring's contrast is measured on the background; on a coloured
  surface, a primary app bar, it can fall below 3:1.
- **A field's label is its name to a screen reader.** A text field, an autocomplete, a number
  field, a select and a date picker take `AutomationProperties.Name` from `PlaceholderText`, and the
  text box inside that takes focus reads the same; an app's own name, or a control it names the
  field with through `AutomationProperties.LabeledBy`, wins on both. Each was announced as an
  unnamed edit box.

### Fixes

- **A user control takes its host's text.** The theme set the body font, size and text-primary on
  every `UserControl`, which beat what it inherited, so one inside a filled button, an app bar or a
  filled alert drew its text in body grey on the colour. They are set on the roots alone now: a
  window, a popup's window and the root a browser or mobile view sits in, which also gives a popup
  `FiliBody2FontSize` where it had the base's fixed 14.

### Licences

- **The package carries the notices of the third-party material in it**, in
  `THIRD-PARTY-NOTICES.md` at its root: the templates forked from Avalonia's Simple theme (MIT),
  eight of which keep the Silverlight Toolkit's Ms-PL header, the Material Icons glyphs
  (Apache-2.0), the values transcribed from MudBlazor (MIT) and Roboto (OFL). Earlier versions
  packed Roboto's licence alone. An app that redistributes the theme's assembly passes the file on
  with it.
- **The licence expression is `MIT AND Apache-2.0 AND MS-PL AND OFL-1.1`**, where it was `MIT`.
  Nothing in the package changed licence; the expression now names what it always bundled. The
  README's licence section says the same; it had said MIT covered all of the XAML.

### High contrast

- **The `dark` colour is a grey**, `#BDBDBD`, 11:1 on black, with black text on it. It was black,
  so `dark` text, links, outlines and avatars were invisible on the black ground. Its hover tint,
  darken and lighten shades follow it.
- **A text or outlined alert's text** is its colour's lighten shade, 5.6:1 or more on its tint; the
  darken shade was 3.4 to 4.4:1.
- **A default chip hovered, focused or pressed** has an opaque grey ground under its white text,
  6.8:1; it was the light disabled grey, 1.5:1.
- **A slider's rail** is its colour at half, 3:1 or more on black; at 30% it was 1.9:1.
- **Three new kinds of key carry these**, each published and declared in every variant:
  `FiliPrimaryAlertTextColor` to `FiliDarkAlertTextColor` (and their brushes), the darken shade in
  light and dark; `FiliChipHoverColor` (and its brush), action-disabled in light and dark; and
  `FiliSliderRailOpacity`, 0.30 in light and dark. An app that overrides a colour in high contrast
  sets its alert text too.

### Docs

- **A Troubleshooting page** on the docs site: a control that is not themed, a key that does
  nothing, a class that does more than asked, and a window half in one variant.
- **`CONTRIBUTING.md` and `SECURITY.md`**: how a change is checked, and how to report a security
  problem privately rather than in an issue.
- **Docs site: a loading bar** while a page opened for the first time is built, so a large page no
  longer looks as if the site has frozen. A page already opened shows at once.

### Docs that promised more than the theme does

- **`FiliThemeVariants.HighContrast`'s documentation** no longer says a variant can be set on any
  control. Set it on the `Application`, as the README and the docs site say: a window's or a
  `ThemeVariantScope`'s variant changes only half of what is in it.
- **A colour is overridden per control by its `*Brush` key**; a `*Color` key in a control's
  `Resources` does nothing, and works in the application's only. The published keys page and the
  Theming page had said any key worked per control.
- **`FiliReducedMotion`** stops the ripple, fades, slides and pulses, but not yet a drawer's slide,
  a switch thumb, floating labels, chevrons, an expansion panel's margin or a circular progress's
  sweep. The README, the published keys page and the Reduced motion page had said it stopped
  everything.
- **The README's class table** is now checked against the theme's classes, as it said it was.
- **The Toggle group page** no longer suggests styling the check mark through its template part.
- **Links fixed:** the [compatibility page](../compatibility.md)'s links to the README's quick start
  and class list, and the base page's to the gallery, lead to their sections again; the README's
  rewrite in 0.26.0 had renamed them.

### The interface and releases

- **The interface 1.0 will promise** is written down in [Compatibility](../compatibility.md): what
  a resource key promises (its name, its type, and that a `*Color` key is set in the application's
  resources while a `*Brush` or glyph key may be set on a control), that the variant is set on the
  `Application`, that the `"HighContrast"` variant string is stable, that the pseudo-classes the
  theme sets and every `Fili*` key not on the published list are implementation, and that a minor
  version may correct accessibility and high contrast and widen what `FiliReducedMotion` covers.
- **The Avalonia dependency is `[12.1.3, 13.0.0)`**: an app moving to Avalonia 13 needs the theme's
  next major version. The DataGrid is themed from 12.1.0 up to but not including 13.0.0, and a 13
  grid is left alone with a warning in Avalonia's log, as an older one already was.
- **The release notes on GitHub are this page** from now on, not a list of commits: a tag whose
  version has no page here, or whose page has no "What changed" list, fails before anything is
  published.
- **The pack validates the package** against the last published one and fails on a public API
  dropped, which every build's tests exercise.
- **A release waits for the maintainer's approval**: the publish job runs in a `nuget` environment
  with a required reviewer, so a pushed tag alone never reaches nuget.org, and every action in the
  workflows is pinned to a commit rather than a tag that can move.
- **The package carries its XML documentation**, so `FiliThemeVariants.HighContrast`'s - where to
  set the variant, how to name it in XAML - shows in an app's editor.

## Upgrading from 0.26.0 to 0.27.0

No class or key is renamed or removed. `FiliFocusRing` is a new key: grep your app for it before
upgrading, as an app's own resource of that name now meets the theme's. A user control in a
coloured host looks different in every variant, a fix, and high contrast in five more ways, each
a correction the [compatibility rules](../compatibility.md) allow in a minor version:

- **Keyboard focus draws a ring**, 2px white, 2px outside the control, over its tint. `False` for
  `FiliFocusRing` in the application's resources keeps the tint alone.
- **The `dark` colour is a grey**, `#BDBDBD` with black text on it, where it was black.
- **A text or outlined alert's text** is its colour's lighten shade, where it was the darken one.
- **A default chip hovered, focused or pressed** has an opaque grey ground, `FiliChipHoverColor`.
- **A slider's rail** is its colour at half, where it was 30%.
- **A user control inside a filled button, an app bar or a filled alert**, or any host that sets
  its text, takes that host's text colour and size instead of body text in text-primary. One that
  wants body text there sets `Foreground` on the user control.
